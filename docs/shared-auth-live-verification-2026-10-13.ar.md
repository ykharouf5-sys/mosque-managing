## فحوص الربط

21 تحققاً على HTTP Kernel الفعلي في Laravel، و23 تحققاً عبر نسخة Next production المنشورة مع Laravel نفسه على MySQL مستعاد ومعزول:

- حساب مُنشأ عبر API التطبيق يدخل من Next، وحساب منشأ عبر Next يدخل من API التطبيق؛ User ID متطابق.
- OTP والتحقق وتحديث ملف الطالب والجلسات تعمل بالعقود الفعلية.
- إضافة مريض عبر Next تظهر عبر مسار التطبيق، وتعديل التطبيق يظهر عبر Next.
- الموعد المضاف عبر مسار التطبيق يظهر عبر Next، والمدفوعات تظهر بالتقارير بالمجموع نفسه.
- حساب آخر لا يصل إلى مريض الحساب الأول، ونطاق حساب قديم يُرفض.
- تسجيل الخروج من Next لا يلغي token التطبيق، وجلسة Next المنتهية تُرفض.
- Cookie الإنتاج Secure وHttpOnly وSameSite=Strict؛ token Laravel لا يُعاد إلى JavaScript.

هذه فحوص على القاعدة المعزولة؛ لم تُنشأ حسابات أو مرضى في إنتاج MySQL. فحوص خدمات Flutter الحقيقية السابقة نجحت في 22 سيناريو مع Laravel وNext وSQLite معزول، بما فيها المتجر والطلبات والمواد وPDF. لا تُعتبر وحدها إثباتاً لكل مسار أكاديمي قديم على إنتاج MySQL.

استخدم الإيميل نفسه وطريقة الدخول نفسها. حساب Google فقط لا يملك بالضرورة كلمة مرور؛ استخدم Google أو استعادة كلمة المرور. بعد تغيير بيانات الموقع افتح التطبيق وحدث/زامن؛ البيانات المحلية غير المزامنة لا تظهر على الخادم. المتجر العام قد ينتظر cache نحو 60 ثانية وخريطة المنتجات نحو 600 ثانية.
